## Bugs fixed on this branch

| | What | Commit |
|---|---|---|
| F1 | **Play in Your Den fails after the launcher was closed and opened again.** The launcher only knew Den Lite as its own child: closing the launcher leaves `den-lite` running (nothing stops it, and the game may still be in it), so the next Play saw the port answer, started nothing, then waited 15 s for "its" child and said "Den Lite started but isn't answering yet" on every try until a reboot. Share with friends couldn't stop it either (the Docker Den would then fight it for port 3724). Now Den Lite writes a heartbeat (`<dens>/den-lite.alive`, every 2 s) and stops when `<dens>/den-lite.stop` appears; the launcher's `host/lite.rs` counts a fresh heartbeat as running, stops such a Den Lite with the stop file, and when something else holds port 3724 says so at once instead of the 15 s wait. Tests: the restart smoke stops the real program with the stop file; `host::lite` test for the heartbeat, the start and the stop. | 2176f76 |
| F2 | "You're live" said "Duel ladder runs Duel ladder" when the realm keeps the mode's name: now "Duel ladder is up." (test in `hostmodes.browser.test.cjs`) | 715f657 |
| | The release smoke itself as a test (`a_new_players_den_survives_a_restart_of_the_program`) | 7d44981 |
| F3 | `.den mods` told every player "Den Lite wasn't told the game folder (--client)": the launcher now passes `--client <game folder>` when it starts Den Lite for a game | 30a2510 |

## The owner must test on a real PC

Only a Windows PC with the game and a friend outside the network can prove these:

1. **A real 3.3.5a client in Den Lite**: it leaves the loading screen, draws the white room, the character dressed, the
   props, Jaina and her walks, and the chat lines (Den Lite README "riskiest unknowns" 1 to 8). Nothing here did this.
2. **Your Den's one click on Windows**: `den-lite.exe` found in `%APPDATA%\Leyline\den-lite\bin`, started hidden (no
   console window), Config.wtf's account filled with DEN, realmlist 127.0.0.1, password `den` works.
3. **Close the launcher and open it again**, press Play in Your Den: it goes straight in (F1), and Share with
   friends stops that Den Lite before the Docker Den starts.
4. **Windows Defender / firewall** on `den-lite.exe` (it listens on 127.0.0.1 only: there should be no prompt).
5. **Forge**: Get Forge downloads and checks the zip, Open in Forge opens on the Den's tile with the flags, saving
   (Ctrl+S) and closing gives "Terrain updated", and the next game start shows the new ground.
6. **Share with friends end to end**: Host pack, Docker Desktop, Start (5 to 20 minutes), the moved Den opens, then a
   **friend outside your network** opens the invite link, makes an account and joins.
7. **Host a server, each template**: the first start (5 to 20 minutes) really finishes, "You're live", the realm on
   the list (public) or the invite (private), and a friend outside joins.
8. **The website's "+ Your server → Start server"** while signed in (not done here: no forms on the live site), the
   downloaded file runs on the PC and the page turns live.
