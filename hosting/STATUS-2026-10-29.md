## 2. Fixed in this branch

* **a. The join page showed one address twice.** The live relay runs beside the official realm, so the
  shared port 3724 is off. The knock then returns the same address as `realmlist` and `realmlist_port`, and
  the page still printed "If the shared address doesn't work, use this one instead" with that same line.
  The page now hides that line when the two are equal (`relay/wurelay/www/join.html`).
* **b. A failed torrent route could leave a bad file behind.** This was in the new transfer code, and was
  caught by its own test.
* **c. The realm list could freeze.** On `/wrath/realms`, if one background refresh of the relay listing
  hung, its lock was never released, and the community list stopped refreshing for good while still
  looking OK. The 19:16 vs 00:10 footer above fits that. The fix:
  * the refresh now releases its lock in a `finally`;
  * a refresh still running after 120 s is replaced (`stream/wrath_portal.py`);
  * a test was added (`stream/tests/test_realms.py`, 39/39).

  Check the footer after the `signin` deploy. If the list was frozen, a portal restart alone would also have
  cleared it.

## 4. Owner steps: a real end-to-end test

**Deploy (Autopilot):**
1. **`hostkit`** publishes the host kit zip as before. It now also runs
   `hosting/pack/make-hostpack.py --upload --write-site`, which:
   * puts `leyline-host-pack-<v>.zip`, its `.torrent` and `hostpack.json` on the `host-pack` release of
     orionopenwow/Leyline;
   * writes `stream/hostpack.json`.

   Commit that file.
2. **`signin`** deploys the portal with:
   * `leyline_net.py` and `hostpack.json`;
   * `/wrath/leyline/flags.json`, all off;
   * the Host pack in `all.json`;
   * the realm-list fix.

   Then check:
   * `https://play.openvanilla.app/wrath/leyline/flags.json` shows every flag `false` and has a `sha256`;
   * `https://play.openvanilla.app/wrath/mods/all.json` has `"id": "mod:host-pack"` with
     `"category": "tools", "kind": "hostpack"`.
3. **`relay`** puts the join-page fix live. It is optional and cosmetic.
4. **`leyline`** ships a launcher build from this branch, so people get the new Host page.

**The test (a friend hosts; you and one more join):**
1. **The host (Windows, with Docker Desktop running)** installs the new Leyline and opens **Host**:
   1. The Docker line says "Docker x is ready". If not, follow its text.
   2. Press **GET THE HOST PACK**. Expect "Host pack <v> installed and checked", and step 2 shows the kit
      folder.
   3. Press **START MY REALM** and answer the questions in the window: name, profile `dalaran`, then
      private. Wait for the first start (5 to 20 minutes).
   4. On **YOUR REALM**, press **REFRESH**. Expect "ONLINE". For a public realm, expect "ON THE REALM LIST"
      within about 1 minute.
   5. Press **COPY INVITE LINK** and send it to the two joiners.
   6. Press **LOGS** and check that the worldserver has said `ready...`.
2. **Joiner 1, from the launcher (desktop 3.3.5a client):**
   1. On **Realms**, paste the invite link and join. Leyline knocks and points `realmlist.wtf` at
      `relay.openvanilla.app:<port>`.
   2. Open the same link in a browser once and make an account there (the password never leaves the
      browser). Then **PLAY** and log in.
   3. Expect the realm in the realm list, character create, and entering the world.
3. **Joiner 2, from the browser:** open the invite link and make an account. Then play in the browser
   client: hop to the realm from play.openvanilla.app/wrath (Leyline hop), which goes in through
   `wss://relay.openvanilla.app/r/<id>/ws/<port>`.
4. **Host: press NEW INVITE LINK.** The old link should now say "this invite link is not valid" to a new
   PC. Players who already knocked keep playing until their 24 hours run out.
5. **Host: press STOP.** The status turns OFFLINE within a minute, and the joiners are disconnected.
   Start it again: characters are still there.
6. **Update check:** run `hostkit` again later, which makes a newer version. The host's card shows
   **UPDATE TO <v>**. After updating, `state/` is untouched: same realm id, same invite link.

**Send back if anything fails:**
* the host's **LOGS** text;
* `Check my realm.bat` output;
* the joiner's error text.

Never send `state/` or `.env`: they hold the realm's key and passwords.

## 5. What stays OFF

**P2P and torrent** are built behind flags that are all off (`docs/P2P-AND-TORRENT.md`):
* direct connections (`p2p_hosting`);
* torrent downloads and seeding;
* WebRTC presence.

To try one on a single PC, use the launcher's **Settings > Advanced**. To turn one on for everyone, use the
admin console (`leyline_net.write_flags`). Nothing P2P ever carries game data or a game client.
